# ADR-0015: سخت‌سازی نهایی و آماده‌سازی استقرار (فاز ۱۷)

**وضعیت:** پذیرفته‌شده | **تاریخ:** 2026-10-19

## زمینه

فاز ۱۷ آخرین فاز پروژه است: بستن حلقه‌های امنیتی، تکمیل هرم تست، تمرین بازیابی فاجعه و مستندات عملیاتی. هیچ فیچر جدیدی اضافه نشد.

## تصمیم‌ها

### ۱. آستانهٔ امنیتی: صفر Critical/High باز
- Semgrep (`--config auto` همان CI + `p/python` + `p/owasp-top-ten`): **۰ خطا**.
- Bandit: یافته‌های باقی‌مانده فقط B613 روی کاراکتر `\u200f` داخل کامنت‌های فارسی‌اند — به‌عنوان false positive پذیرفته و مستند شدند (`docs/security/phase17-findings.md`)، چون حذفشان متن فارسی را خراب می‌کند.
- یافته‌های واقعی رفع شدند: rate-limit روی `/api/v1/voice/*` (جلوگیری از تخلیهٔ هزینهٔ STT/TTS)، XSS در `build_embed_snippet`، سخت‌سازی کوئری pgvector.
- تست‌های حمله (SQLi، دست‌کاری JWT، IDOR، replay وبهوک پرداخت، دسترسی مستقیم به فایل خصوصی بدون URL امضادار) همه سبز‌اند: `apps/api/tests/test_security_phase17.py`.

### ۲. هرم تست کامل شد
- **۴۱۱ passed + ۳ xfailed** (سوئیت کامل). تست‌های جدید فاز ۱۷: golden vectorهای فقهی (موتور ارث/زکات روی فیکسچر synthetic، پین‌شده)، eval قطعی RAG، replay وبهوک، سناریوهای تعارض sync، GDPR واقعی (export/delete با راستی‌آزمایی در DB)، E2E سرتاسری، و خط لولهٔ axe-core (صفر تخلف در ۵ صفحه).
- ۳ شکاف export در GDPR به‌صورت xfail **صریح و مستند** رها شدند (نه پنهان).

### ۳. RPO/RTO و DR
- RPO=۲۴h (بکاپ روزانه)، RTO=۴h. تمرین بازیابی **واقعی** در 2026-10-19 موفق بود (بخش ۴ runbook).
- بکاپ روی همان سرور کافی نیست — کپی off-site هفتگی الزامی است.

### ۴. مسیر رشد
- API از ابتدا stateless طراحی شد؛ تنها استثنا WebSocket gateway است که برای چند replica به Redis adapter نیاز دارد (در `docs/operations/scaling.md` مستند شد، نه اینکه پنهان بماند).

## پیامدها
- استقرار تولید = `docker compose up -d` + اجرای runbook. بدون سورپرایز معماری.
- بدهی‌های شناخته‌شده (۳ xfail، WebSocket adapter، موتور جست‌وجوی تمام‌متن در مقیاس بالا) مستند و قابل پیگیری‌اند.
