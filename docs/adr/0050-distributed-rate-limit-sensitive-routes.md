# ADR-0050 — تکمیل مهاجرت محدودیت نرخ توزیع‌شده: دانلود کتابخانه و استعلام گواهی

## زمینه
محدودکنندهٔ توزیع‌شده (Redis) از remediation-pass-2 برای احراز
هویت و عملیات ادمین برقرار بود، ولی دو مسیر حساس هنوز روی
`rate_limiter` درون‌حافظه‌ایِ `app.core.security` بودند:
استریم/دانلود کتابخانه (`library_stream`، ‏۶۰/دقیقه/IP) و استعلام
عمومی گواهی (`cert_verify`، ‏۳۰/دقیقه/IP). حافظهٔ درون‌فرایندی بین
workerها مشترک نیست؛ با N worker سقف واقعی N برابر می‌شد — نقض
مستقیم قرارداد §۱۹.۳ (هر state اثرگذار بر مقیاس باید پیش از
scale افقی به Redis برود).

## تصمیم
- هر دو مسیر به `get_rate_limiter()` (DistributedRateLimiter)
  مهاجرت کردند؛ سقف‌ها و کلیدسازی دقیقاً همان قبلی است (همان
  namespaceها، همان سقف/IP) — فقط بک‌اند عوض شد.
- معنای Redis-down برای این مسیرها همان معنای مسیرهای احرازهویتی
  است (`auth=True` در API limiter): در production با Redisِ قطع
  fail-closed (429 صریح)، در dev/test fallback حافظه‌ای با لاگ.
  دلیل: این‌ها مسیر حساس‌اند (دانلود و endpoint عمومی بدون احراز
  که هدف scraping است)؛ بازشدن بی‌صدا در production یعنی حذف
  عملی سقف، و رفتار باس رویداد (FIX2-05) هم همین الگوست.
- بقیهٔ ممیزی: احراز هویت، کپچا (در مسیر register)، عملیات ادمین
  و دکوراتور `rate_limit` از قبل توزیع‌شده بودند؛ کاربر دیگری از
  limiter درون‌حافظه‌ای در کد production باقی نماند.
- کلاس قدیمی `RateLimiter` در `app.core.security` حذف نشد ولی
  صریحاً LEGACY علامت خورد: هیچ مسیر productionی از آن استفاده
  نمی‌کند و فقط چند تست قدیمی singleton آن را برای reset صدا
  می‌زنند. کد تازه هرگز نباید از آن استفاده کند.

## پیامدها
- اثبات چندپردازه‌ای واقعی در تست‌ها: دو پردازهٔ جدا با کلاینت
  واقعی Redis روی یک بک‌اند مشترک، مجموع مجازها دقیقاً سقف است
  (نه سقف×پردازه). بک‌اند تست یک سرور RESP مینیمال است چون
  redis-server در sandbox نیست؛ خاصیت مورد اثبات (شمارندهٔ
  اتمیک مشترک بیرون از پردازه‌ها) همان است که با Redis واقعی
  هم برقرار است.
- در production اگر Redis نباشد، دانلود/استعلام 429 می‌گیرند —
  عمدی و بلند (لاگ error)، نه سقوط و نه بازشدن.

## جایگزین‌های ردشده
- نگه‌داشتن سقف درون‌حافظه‌ای برای این دو مسیر «چون کم‌ترافیک‌اند»:
  قرارداد §۱۹.۳ استثنا نمی‌شناسد و سقفِ ضربدری دقیقاً در حملات
  scraping معنا پیدا می‌کند.
- fail-open در production برای دانلود: حذف سقف در بدترین لحظه
  (قطع Redis هم‌زمان با سوءاستفاده)؛ برخلاف الگوی fail-closed
  تثبیت‌شدهٔ همین کدبیس.
