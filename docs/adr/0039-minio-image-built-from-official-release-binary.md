# ADR-0039 — ایمیج MinIO از باینری رسمی release ساخته می‌شود

- وضعیت: پذیرفته‌شده — ۲۰۲۶-۱۰-۲۲ (رفع اشکال‌های audit روی 197efa0)

## زمینه
هر دو compose ایمیج MinIO را از `quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z`
می‌گرفتند، با این فرض (Track B) که بعد از حذف ایمیج‌ها از Docker Hub،
«همان ایمیج با digest یکسان روی quay.io منتشر می‌شود». اولین اجرای واقعی
job ‏compose-smoke در CI (C-04، ‏PR #16) این فرض را رد کرد:

- ‏quay.io برای آن ریپو «401 UNAUTHORIZED» روی HEAD مانیفست می‌دهد.
- راستی‌آزمایی مستقل: با توکن ناشناس quay، ‏`tags/list` برای
  ‏`minio/minio` ‏401 است ولی برای ریپوهای عمومی دیگر (مثل
  ‏prometheus) ‏200 — یعنی خود ریپو برای pull ناشناس بسته/حذف شده،
  نه مشکل کلاینت.
- Docker Hub هم ریپوی `minio/minio` را دیگر ندارد («repository does
  not exist»). باینری archive روی dl.min.io هم 410 Gone است.

نتیجه: استک production (و dev) روی هیچ ماشین تازه‌ای بالا نمی‌آمد —
دقیقاً همان کلاس خطای محیط واقعی که C-04 قرار بود قبل از لانچ بگیرد.

## تصمیم
1. ایمیج MinIO از **باینری رسمی همان release روی GitHub** ساخته
   می‌شود: `infra/minio/Dockerfile` (پایهٔ alpine پین‌شده)، با
   **sha256 رسمیِ فایل ‎`.sha256sum` همان release** برای هر دو
   معماری amd64/arm64؛ نسخه دقیقاً همان پین قبلی می‌ماند
   ‏(`RELEASE.2025-09-07T16-13-09Z`) — latest هیچ‌جا استفاده نمی‌شود.
2. هر دو compose به‌جای رفرنس quay از `build: ./infra/minio` با
   تگ محلی `maturidi/minio:RELEASE.2025-09-07T16-13-09Z` استفاده
   می‌کنند؛ بقیهٔ قرارداد سرویس (command، env، ‏healthcheck با
   ‏curl، والیوم `/data`) بدون تغییر می‌ماند.

## پیامدها
- استک دوباره روی ماشین تازه قابل `up` است و smoke ‏CI می‌تواند
  سبزشدن آن را ثابت کند.
- هزینه: یک build کوتاه اضافی در اولین `up` (دانلود ~۱۰۰MB از
  GitHub و راستی‌آزمایی چک‌سام)؛ بعد از آن ایمیج کش می‌شود.
- اگر MinIO روزی رجیستری عمومی‌اش را برگرداند، برگشت به ایمیج آماده
  یک تغییر تک‌خطی در هر compose است.
