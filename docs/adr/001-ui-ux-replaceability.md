# ADR-001: جداسازی کامل UI/UX از منطق — رابط کاربری باید قابل «کوبیدن و بازسازی از نو» باشد

- وضعیت: پذیرفته‌شده (دستور مستقیم کاربر)
- تاریخ: 2026-10-18
- تصمیم‌گیرنده: حسینه (مالک پروژه)

## زمینه

کاربر اعلام کرد بعداً می‌خواهد کل UI/UX را از نو بسازد. بنابراین از همین حالا ساختار کد
باید طوری باشد که حذف کامل لایهٔ نمایش و بازنویسی آن، هیچ تغییری در منطق کسب‌وکار،
لایهٔ داده یا قراردادهای API لازم نداشته باشد.

## تصمیم

۱. **هیچ منطق کسب‌وکاری داخل کامپوننت‌ها نیست.** کامپوننت‌ها (در `apps/*/…` و
   `packages/ui-*`) فقط نمایش و تعامل کاربر هستند: props می‌گیرند، event بالا می‌دهند.
۲. **همهٔ منطق در لایه‌های غیرنمایشی:** هوک‌ها/سرویس‌ها/توابع خالص، فراخوانی API از
   طریق کلاینت‌های متمرکز (`lib/api` و مشابه)، و تایپ‌های مشترک در
   `packages/shared-types`.
۳. **قراردادهای API پایدار** می‌مانند؛ بازسازی UI هرگز نباید نیاز به تغییر
   بک‌اند داشته باشد.
۴. **توکن‌های طراحی و کتابخانه‌های کامپوننت** (`packages/design-tokens`، `ui-web`،
   `ui-native`، `icons`) به منطق دامنه وابسته نمی‌شوند تا با بازطراحی، یکجا
   قابل جایگزینی باشند.
۵. هر صفحه/فلو باید با این تست ذهنی پاس شود: «اگر کل پوشهٔ صفحات و کامپوننت‌های
   این اپ را حذف و از صفر بنویسم، آیا بدون دست زدن به بک‌اند/سرویس‌ها/قراردادها
   ممکن است؟» اگر نه، ساختار اشتباه است و باید اصلاح شود.

## پیامدها

- مثبت: بازطراحی آینده کم‌ریسک و سریع؛ امکان برون‌سپاری یا تعویض تیم UI
  بدون درگیر شدن با هستهٔ سیستم.
- منفی: کمی سربار اولیه (لایه‌بندی بیشتر، ممنوعیت منطق در کامپوننت).
- این ADR بر همهٔ فازهای جاری و آینده (از جمله ادامهٔ فاز ۲) لازم‌الاجراست.
