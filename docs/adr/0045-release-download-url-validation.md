# ADR-0045 — اعتبارسنجی download_url انتشار و اعمال انقضا هنگام سرو

## زمینه
`ReleaseCreateIn.download_url` هر رشته‌ای را می‌پذیرفت و خروجی
release آن را بدون بررسی scheme/host و بدون اعمال
`download_expires_at` برمی‌گرداند. این لینک در CRM «دانلود رسمی
بیلد امضاشده» است؛ URL خارجی دلخواه یعنی لینک فیشینگ/بدافزار با
ظاهر رسمی، و انقضای ثبت‌شده صرفاً نمایشی بود و لینک مرده/منقضی
برای همیشه سرو می‌شد.

## تصمیم
- هنگام ثبت (فقط مسیر signed که URL واقعاً ذخیره و سرو می‌شود)
  `validate_download_url` اجرا می‌شود: scheme فقط https (http فقط
  برای localhost توسعه) و hostname فقط از میان میزبان‌های شناخته‌شدهٔ
  پروژه: `S3_ENDPOINT_PUBLIC`، `BUILDS_S3_ENDPOINT_PUBLIC` و
  `APP_BASE_URL`. userinfo و whitespace رد می‌شود. اگر هیچ میزبان
  عمومی‌ای پیکربندی نشده باشد، download_url دستی رد می‌شود و مسیر
  درست `artifact_key` (باکت builds — ADR-0041) است.
- هنگام سرو (`_release_out`، تنها سطح خروجی release) اگر
  `download_expires_at` گذشته باشد، URL داده نمی‌شود و
  `download_expired: true` برمی‌گردد تا CRM دلیل را نشان دهد.
- تست موجود فاز ۱۴ که URL خارجی دلخواه (example.com) را قفل کرده
  بود به میزبان مجاز (localhost از APP_BASE_URL) به‌روز شد؛ رفتار
  «امضانشده → لینک ذخیره نمی‌شود» دست‌نخورده ماند.

## پیامدها
- ثبت دستی release با لینک بیرون از زیرساخت پروژه ناممکن است.
- انقضا از حالت نمایشی به اعمال واقعی رسید؛ رکورد و تاریخ انقضا
  همچنان در خروجی می‌ماند تا اپراتور ببیند و تمدید کند.

## جایگزین‌های ردشده
- فقط https بدون قید میزبان: فیشینگ با دامنهٔ https هم ممکن است.
- حذف فیلد download_url: مسیر ثبت دستیِ بیلد امضاشدهٔ قدیمی هنوز
  مصرف دارد؛ محدودسازی آن کافی و کم‌ریسک‌تر از حذف است.
