# ADR-0024: حذف پنجرهٔ اغماض تشخیص reuse رفرش‌توکن؛ قفل رفرش سمت کلاینت

- وضعیت: پذیرفته‌شده — تصمیم ۲ ADR-0020 (پنجرهٔ اغماض ۶۰ ثانیه‌ای) را نسخ می‌کند
- تاریخ: 2026-10-22
- میل‌استون: ممیزی مستقل روی 197efa0 — مورد B-02

## زمینه

ADR-0020 برای تشخیص استفادهٔ مجدد از رفرش‌توکن یک پنجرهٔ اغماض ۶۰ ثانیه‌ای
گذاشته بود: اگر جانشینِ توکن باطل‌شده ≤۶۰ ثانیه عمر داشت، ارائهٔ دوبارهٔ
توکن قدیمی «race هم‌زمان مشروع» فرض می‌شد و از تازه‌ترین توکن زنده چرخش
می‌شد. ممیزی مستقل (B-02) نشان داد این یعنی توکن دزدیده‌شده در آن پنجره
کاملاً کار می‌کند و سرور بی‌سروصدا (بدون audit/event) جفت‌توکن تازه صادر
می‌کند — نقض قرارداد فاز ۰ §۲ («هر استفاده، توکن قبلی را باطل می‌کند»).

## تصمیم

1. **سرور سخت‌گیر است:** ثابت `REUSE_DETECTION_GRACE_SECONDS` و هر دو شاخهٔ
   اغماض (در `refresh_pair` و fallback «بازندهٔ race» در `_rotate_token`)
   حذف شدند. هر ارائهٔ توکن باطل‌شده — در هر زمانی، حتی ثانیهٔ ۱ یا ۵۹ —
   یعنی: ابطال فوری کل نشست (برای توکن‌های بی‌نشست: همهٔ نشست‌های کاربر)
   + رویداد `token.reuse_detected` + audit + پاسخ 401.
   ادعای اتمیک چرخش (`UPDATE ... WHERE revoked=FALSE`) برقرار است؛
   بازندهٔ ادعا همان مسیر reuse را می‌رود.
2. **race مشروع در کلاینت حل می‌شود:** کلاینت‌های وب (`apps/web/lib/auth-client.ts`)
   و CRM (`apps/crm/src/lib/api.ts`) رفرش را با single-flight درون‌تب +
   قفل بین‌تبی Web Locks (`navigator.locks`, نام قفل `ma.auth.refresh`)
   انجام می‌دهند و داخل قفل، جفت‌توکن را از storage دوباره می‌خوانند —
   اگر تب دیگری چرخش را انجام داده باشد، جفت ذخیره‌شده پذیرفته می‌شود و
   توکن کهنه هرگز به سرور ارائه نمی‌شود. بدون Web Locks، single-flight
   درون‌تب fallback است.

## پیامدها

- کلاینتی که بدون این قفل توکن چرخش‌خورده را دوباره بفرستد (کلاینت قدیمی
  یا اسکریپت دستی)، نشست را از دست می‌دهد — رفتار موردنظر تشخیص سرقت.
- تست‌های رفتار قدیمی (اغماض) به قرارداد جدید بازنویسی شدند؛ تست‌های
  چرخش عادی و reuse با فاصلهٔ زمانی بدون تغییر سبز می‌مانند.
- هیچ تغییر breaking در شکل API نیست؛ فقط پاسخ به ارائهٔ توکن باطل‌شده
  از «200 در پنجره» به «401 همیشه» تغییر کرد.

## جایگزین‌های ردشده

- نگه‌داشتن اغماض کوتاه‌تر (مثلاً ۵ ثانیه): همان حفره، کوچک‌تر — رد شد.
- اغماض فقط برای همان IP/دستگاه: IP قابل جعل/اشتراک است و دستگاه قابل
  اثبات نیست — رد شد.
