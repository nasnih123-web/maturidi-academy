# ADR-0031 — حذف کانفیگ کهنهٔ دسکتاپ، تصمیم آپدیتر، و صداقت prereqs بیلد (C-05)

وضعیت: پذیرفته‌شده (رفع اشکال حسابرسی 197efa0، آیتم C-05)
تاریخ: ۲۰۲۶-۱۰-۲۲

## تصمیم‌ها

۱) **کانفیگ ریشهٔ دسکتاپ حذف شد.** ‏apps/desktop/tauri.conf.json یک
کپی واگرای کهنه بود (آپدیتر فعال با endpoint ساختگی، پورت/مسیر
غلط) که در v1.1.0 برای بازبینی مالک نگه داشته شده بود (ADR-0023).
حسابرسی دستور حذف داد: تنها کانفیگ معتبر
‏src-tauri/tauri.conf.json است و هیچ ابزاری نباید به مسیر ریشه
ارجاع دهد.

۲) **آپدیتر Tauri صریحاً غیرفعال می‌ماند** ‏(updater.active=false)
تا وقتی هاست releases واقعی + کلید امضای updater وجود داشته باشد؛
و فهرست ‏endpoints **خالی** است — هیچ نشانی placeholder/‏example.com
در کانفیگ نمی‌ماند. فعال‌سازی آینده فقط با endpoint واقعی +
pubkey واقعی و یک ADR جدید.

۳) **مدل صداقت prereqs:** ‏GET /api/v1/admin/builds/prereqs حالا سه
لایه را جدا گزارش می‌کند: (الف) امضاها و پلتفرم‌ها (مثل قبل)،
(ب) ‏pipeline — فقط آنچه خود API می‌تواند ببیند: توکن callback
بیلد (B-01) تنظیم شده؟ dispatch گیت‌هاب پیکربندی شده؟ نشانی عمومی
API چیست و آیا localhost است؟ پروژهٔ Expo لینک شده؟ (شناسه در
تنظیم ‏builds.expo_project_id که مالک پس از ‏eas init در CRM ثبت
می‌کند)، (ج) ‏ci_side — پیش‌نیازهایی که در GitHub Secrets/EAS
زندگی می‌کنند (EXPO_TOKEN، اسرار callback و S3، keystore و
گواهی‌های امضا) با ‏api_visible=false و محل راستی‌آزمایی واقعی‌شان
(preflight ورک‌فلو). CRM هر سه لایه را نشان می‌دهد؛ هیچ موردی
بدون مدرک «آماده» نمایش داده نمی‌شود.

۴) **اجرای آزمایشی بیلد** تا رسیدن فایل نهایی همچنان owner-gated
است (ابزار dispatch در دسترس agent نیست)؛ همهٔ چیز تا آن مرز —
preflight صادقانهٔ ورک‌فلو، callback ‏B-01، prereqs کامل — آماده
است و راهنمای مالک در docs/ops/APK_BUILD_GUIDE.md به‌روز شد.
