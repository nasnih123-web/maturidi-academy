# ADR-0048 — env صریح توسعهٔ محلی برای bootstrap + چک‌لیست سلامت واقعی

## زمینه
bootstrap قالب production (`.env.example`) را کورکورانه به `.env`
کپی می‌کرد و فقط یک خط CORS برای API می‌نوشت. نتیجه روی ماشین
توسعه: `CAPTCHA_ENABLED=true` بدون secret یعنی ثبت‌نام fail-closed
با 503؛ `CLAMAV_HOST=clamav` بدون compose یعنی آپلود fail-closed
با 503؛ و «موفقیت» فقط با بالا آمدن پورت‌ها اعلام می‌شد. نصبِ
به‌ظاهر موفق، در عمل برای دو جریان اصلی خراب بود.

## تصمیم
- `tools/dev/write_dev_env.py` (مشترک بین bootstrap.sh و
  bootstrap.ps1) هر دو `.env` ریشه و `apps/api/.env` را با یک env
  صریحِ فقط-dev می‌سازد: APP_ENV=dev، SQLite محلی، secretهای
  تصادفی تازه برای همان نصب، و دو انحراف آگاهانه با هشدار داخل
  فایل: `CAPTCHA_ENABLED=false` (دلیل مستند) و
  `CLAMAV_ALLOW_INSECURE_DEV_BYPASS=true` (پرچم ناامنِ فقط-dev
  خود پروژه از C-01؛ در غیر dev بی‌اثر و هر استفاده‌اش CRITICAL
  لاگ می‌شود). فایل موجود هرگز بازنویسی نمی‌شود.
- `tools/dev/bootstrap_check.py` (فقط stdlib) موفقیت را به سه چک
  واقعی روی سرویس زنده گره می‌زند: `/health`، ثبت‌نام+ورود یک
  کاربر تازه، و آپلود WAV از مسیر واقعی C-01 (پاس = 200 یا
  `stt_unavailable` بعد از اسکن موفق؛ `antivirus_unavailable`
  یعنی شکست). هر شکست: چک‌لیست با علت چاپ و خروج غیرصفر — بنر
  موفقیت چاپ نمی‌شود.
- گارد production دست نخورد: نه CAPTCHA و نه ClamAV در هیچ محیط
  غیر dev ضعیف نشده‌اند.

## پیامدها
- بوت‌استرپ محلی از جعبه کار می‌کند و ادعای موفقیتش قابل راستی‌آزمایی
  است (روی API واقعی در محیط توسعه اجرا و هر سه چک سبز شد).
- هزینهٔ صادقانه: هر اجرای bootstrap یک کاربر synthetic با پیشوند
  bootstrap-check در دیتابیس dev می‌سازد (قابل حذف دستی).

## جایگزین‌های ردشده
- اجرای compose کامل برای dev محلی: bootstrap عمداً بدون Docker
  طراحی شده (ماشین کاربر) و سنگین‌کردنش مسیر اصلی را عوض می‌کرد؛
  wiring درست ClamAV در compose از قبل در آیتم smoke (FIX2-10)
  پوشش دارد.
- ساخت clamd جاسازی‌شده در bootstrap: وابستگی باینری خارجی و
  نگهداری تازه؛ پرچم dev موجود دقیقاً برای همین ساخته شده است.
