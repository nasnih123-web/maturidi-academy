# ADR-0025 — بستن حلقهٔ بیلد: callback سرویس CI + فایل واقعی در MinIO (B-01)

وضعیت: پذیرفته‌شده (رفع اشکال حسابرسی 197efa0، آیتم B-01)
تاریخ: ۲۰۲۶-۱۰-۲۲

## زمینه

یافتهٔ Blocker حسابرسی: «آخرین حلقهٔ» مرکز بیلدها هرگز بسته نشده بود —
هیچ‌کدام از workflowهای mobile/desktop بعد از ساخت، نتیجه را به API
برنمی‌گرداندند؛ BuildRelease فقط دستی ساخته می‌شد و برای بیلد واقعی
هیچ‌وقت download_url نداشت، پس دکمهٔ دانلود CRM همیشه غیرفعال بود —
در حالی که UI طوری به نظر می‌رسید که انگار این جریان کار می‌کند.

## تصمیم

۱) **توکن سرویس اختصاصی CI** (`BUILDS_SERVICE_TOKEN` در محیط API،
نام secret متناظر در GitHub: `BUILDS_SERVICE_TOKEN`): تنها مسیر
ماشینیِ ثبت انتشار، POST /api/v1/admin/builds/releases با هدر
`X-Build-Service-Token` است؛ مقایسه ثابت‌زمان (hmac.compare_digest)
و فقط وقتی توکن در محیط تنظیم شده باشد فعال است. مسیر کاربرِ دارای
مجوز `builds.manage` دست‌نخورده می‌ماند. ثبتِ سرویس با
actor_type="service" و released_by=NULL ممیزی می‌شود.

۲) **فایل واقعی در StorageProvider**: workflow فایل ساخته‌شده را با
`tools/ci/build-callback.sh` به باکت builds می‌فرستد (کلید
`builds/<platform>/<version>/<build_number>/<file>` با دسترسی
S3 از GitHub Secrets) و فقط متادیتا (artifact_key, file_size_bytes,
sha256) را به API ثبت می‌کند. سه ستون nullable با مهاجرت روبه‌جلو
`d1a2b3c4e5f6` اضافه شد؛ ردیف‌های قدیمی بدون فایل می‌مانند.

۳) **download_url تازه و کوتاه‌عمر**: پاسخ release هر بار از روی
artifact_key با `get_presigned_url` (TTL ‏۹۰۰ ثانیه) ساخته می‌شود و
در DB ذخیره نمی‌شود؛ endpoint فقط برای مدیرِ دارای مجوز است، پس
بیلد داخلیِ امضانشده هم قابل دانلود است و پرچم `signed` + برچسب
«امضانشده» در CRM (C-05) وضعیت امضا را جداگانه و صادقانه نشان
می‌دهد. مسیر قدیمیِ download_url ذخیره‌شده فقط برای بیلد امضاشده
برگردانده می‌شود.

۴) **نگهداری**: پس از هر ثبت، فقط ۱۰ بیلد آخر هر پلتفرم می‌ماند؛
رکورد اضافه حذف و فایلش از storage پاک می‌شود (حذف فایل
best-effort + لاگ).

۵) **صداقت workflow**: نبود هرکدام از secretهای BUILDS_* یعنی
callback با هشدار رد می‌شود (exit 0) و در گزارش بیلد صریح می‌آید که
انتشار ثبت نشده است — هرگز موفقیت جعلی گزارش نمی‌شود.

## پیامدها

- اثبات اجرای واقعی workflow_dispatch در محیط مالک می‌ماند
  (ابزار dispatch در دسترس نیست) — کد + تست + اسکریپت تحویل است.
- چرخش توکن سرویس = تغییر هم‌زمان env API و GitHub Secret؛ بدون
  دورهٔ هم‌پوشانی (پنجرهٔ کوتاه قطعیِ callback هنگام چرخش پذیرفته
  شده است، چون ثبت انتشار دستی هم همیشه ممکن است).
