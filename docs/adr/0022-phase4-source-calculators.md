# ADR-0022: یکپارچه‌سازی ماشین‌حساب‌های منبع (فاز ۴) — قالب‌های rule_data افزوده و endpointهای بی‌حالت

- وضعیت: پذیرفته‌شده
- تاریخ: 2026-10-21
- میل‌استون: Master Execution Prompt v2 — Phase 4 (source calculators)

## زمینه

فاز ۷ سیستم ماشین‌حساب‌ها را با rule-configهای نسخه‌دار و دروازهٔ بازبینی
علمی ساخت (ADR-0006). سه صفحهٔ مستقلِ منبع (زکات، فرائض بر مبنای سراجیه،
مُصَرِّف افعال) — منسوب به مهران ساعدی، بدون متن مجوز — باید در همین سیستم
ادغام می‌شدند، نه در سیستمی موازی:

- زکاتِ منبع مدل «پلکانی» و جدول‌های نصاب دام دارد که در قالب Phase-7
  (`asset_categories`) نمی‌گنجد.
- موتور فرائض منبع یک pipeline کامل سراجیه است؛ موتور ارث Phase-7 ساده‌تر
  است و سهم‌هایش از `rule_data.shares` خوانده می‌شود.
- مُصَرِّف فقهی نیست و نباید پشت دروازهٔ علمی قفل شود.
- مجوز منبع نامشخص است ⇒ کپی لفظ‌به‌لفظ کد یا نثر ممنوع؛ فقط بازپیاده‌سازی
  قواعد با کد اصیل مجاز است (رک: `docs/calculators/CALCULATORS_INTEGRATION.md`
  و `THIRD_PARTY_NOTICES.md`).

## تصمیم

1. **قالب‌های افزوده داخل همان `rule_data`:** زکات منبع زیر کلید `extended`
   با نشان قالب `source_extended_v1` و فرائض زیر کلید `miras` با نشان
   `miras_v1` ذخیره می‌شوند. کانفیگ‌های Phase-7 دست‌نخورده می‌مانند؛ هر
   kind می‌تواند هر دو قالب را هم‌زمان داشته باشد.
2. **سید نسخهٔ ۲ پیش‌نویس (DRAFT):** هر دو کانفیگ منبع با وضعیت draft و
   منبع «مهران ساعدی — source calculators» سید می‌شوند. دروازهٔ عمومی
   **بسته می‌ماند** تا بازبینی و تأیید علمی انجام شود.
3. **انتخاب بر اساس کلید payload:** `get_active_rule` پارامتر `require_key`
   گرفت؛ هر endpoint جدیدترین کانفیگ تأییدشده‌ای را می‌گیرد که کلید خودش
   را دارد (`shares` / `asset_categories` برای Phase-7، `miras` /
   `extended` برای فاز ۴). قالب‌ها همدیگر را shadow نمی‌کنند و تأیید یک
   قالب، قالب دیگر را باز نمی‌کند و برعکس.
4. **Endpointهای جدیدِ بی‌حالت:** `POST /calculators/zakat/extended`،
   `POST /calculators/inheritance/miras` و `POST /calculators/mosaref`
   هیچ ردیف caseای نمی‌نویسند و ورودی مالی/خانوادگی کاربر را ذخیره
   نمی‌کنند. توقف تقسیم ارث (مانع، نبود وارث، ناتمامی مجموع، چندشاخگی
   ذوی‌الارحام) نتیجهٔ فقهی است و با HTTP 200 و `status: "stopped"` و
   `stop_code` پایدار برمی‌گردد، نه خطای سرور.
5. **دقت عددی:** پول فقط Decimal؛ سهم‌الارث فقط `fractions.Fraction`.
   مصنوعات float منبع (مثلاً طلای ۱۴۷٫۲ گرم) و مصنوعات رندر HTML آن
   (جایگاه همزهٔ ابتدای سلول) عمداً بازتولید نشدند و در سند یکپارچه‌سازی
   به‌عنوان انحراف مستند ثبت شده‌اند.
6. **تست طلایی از خود منبع:** خروجی صفحات اصلی در Node اجرا و به‌صورت
   fixture داده‌ای (نه کد) ذخیره شد؛ موتورها باید ۱۰۰٪ با باتری
   (۱۳۱ زکات + ۵۳ فرائض + ۴۱ مُصَرِّف) منطبق باشند.

## پیامدها

- بازبینی علمی هر قالب مستقل است: تأیید زکات منبع، ارث Phase-7 را باز
  نمی‌کند و برعکس.
- قرارداد §15.10/§15.11 بدون تغییر می‌ماند؛ این ADR صرفاً قالب‌های
  دادهٔ افزوده و سه endpoint افزوده را ثبت می‌کند.
- UI وب برای هر سه ابزار از همان الگوهای Phase-7 استفاده می‌کند
  (وضعیت pending صادقانه هنگام بسته‌بودن دروازه؛ ADR-0001/0002).
