# ADR-0033 — جست‌وجوی سراسری: تجمیع چهار منبع + امتیاز ترکیبی (M-01)

وضعیت: پذیرفته‌شده (رفع اشکال حسابرسی 197efa0، آیتم M-01)
تاریخ: ۲۰۲۶-۱۰-۲۲

## زمینه

‏GET /api/v1/search از فاز ۳ فقط بخش‌های خانه و تم‌ها را می‌گشت.
حسابرسی M-01 تجمیع واقعی روی فتوا + کتابخانه + دوره + صفحهٔ CMS با
امتیاز ترکیبی و فیلتر نوع را الزام می‌کند.

## تصمیم

۱) منابع (فقط رکورد عمومی/منتشرشده): فتوا (workflow=published)،
کتابخانه (published + visibility=public)، دوره (active + public)،
صفحه (published). پیش‌نویس/خصوصی هرگز سطح نمی‌شود (تست اختصاصی).

۲) امتیاز ترکیبی: واژگانی (وزن‌های فاز ۳: عنوان پیشوندی ۲٫۰ /
درون‌رشته‌ای ۱٫۰؛ متن ۱٫۵ / ۰٫۵) + تازگی (≤۰٫۱۵، افت خطی ۱۸۰
روزه از published_at/created_at) + محبوبیت (≤۰٫۱۵، log-نرمال‌شده)
+ معنایی (≤۰٫۳، فقط فتوا). **صداقت محبوبیت:** تنها سیگنال مشارکت
واقعیِ موجود در داده، ثبت‌نام دوره‌هاست (CohortEnrollment)؛ برای
بقیهٔ منابع شمارندهٔ بازدید/دانلود وجود ندارد و مؤلفه صفر است —
شمارندهٔ ساختگی ساخته نشد. تابع امتیاز ورودی محبوبیت می‌گیرد تا
با آمدن سیگنال واقعی، سیم‌کشی یک‌خطی شود.

۳) پای معنایی فقط وقتی provider واقعی embedding فعال است فعال
می‌شود (با hash — پیش‌فرض dev/test — عمداً خاموش است تا نویز
شبه‌تصادفی وارد رتبه‌بندی نشود) و بهترین‌تلاش است: خطاهایش هرگز
جست‌وجوی واژگانی را خراب نمی‌کند. پیوند chunk→submission از
‏source_ref.id (قرارداد ingestion) خوانده می‌شود.

۴) روش اسکن: ستون‌های JSONB روی SQLite به‌صورت unicode-escaped
ذخیره می‌شوند و پیش‌فیلتر SQL روی متن آن‌ها قابل‌اتکا نیست
(اثبات شد)؛ پس هر منبع با سقف ۵۰۰ رکورد تازهٔ منتشرشده اسکن و در
پایتون امتیازدهی می‌شود — همان الگوی جست‌وجوی خود کتابخانه، روی
هر دو دیالکت یکسان. مسیر ارتقای آینده برای کاتالوگ‌های بسیار
بزرگ: PG FTS/pg_trgm سمت دیتابیس (§۸) بدون تغییر قرارداد API.

۵) وب: صفحهٔ جست‌وجو حالا پارامتر ‏type را از URL می‌خواند و به
searchApi می‌دهد (خود کلاینت از فاز ۳ type را پشتیبانی می‌کرد) +
چیپ‌های فیلتر نوع (fa/ar/en). نام‌های نوع fatwa/library/course/
page از قبل در i18n وب بودند؛ library به‌جای book استفاده شد چون
کلید type واقعی همین است (book/article/verse کلیدهای رزرو آینده‌اند).

۶) تست فاز ۳ ‏test_search_prefix_beats_substring که رتبهٔ مطلقِ
بخش‌ها را در فهرست تک‌منبعی قفل می‌کرد، شفاف به نیت اصلی‌اش
(پیشوند > درون‌رشته در میان نتایج section) بازنویسی شد — همین
ADR مستند آن است (رویهٔ B-02/ADR-0024).
