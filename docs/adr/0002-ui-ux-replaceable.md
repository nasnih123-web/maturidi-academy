# ADR 0002 — جدایی کامل UI/UX از منطق کسب‌وکار

تاریخ: 2026-10-18 — دستور مستقیم کارفرما

## تصمیم

کل لایهٔ نمایش (UI/UX) باید طوری ساخته شود که بتوان آن را **کاملاً تخریب و از صفر بازسازی کرد، بدون اینکه به منطق کسب‌وکار یا لایهٔ داده دست زده شود.**

## قواعد الزامی

1. **هیچ منطق کسب‌وکاری داخل کامپوننت‌ها نیست.** کامپوننت‌ها فقط render می‌کنند.
2. تمام منطق از طریق **hookها / سرویس‌ها / قراردادهای API پایدار** مصرف می‌شود.
3. Design tokenها و کتابخانه‌های کامپوننت در **پکیج‌های جدا** (`packages/design-tokens`، `packages/ui-web`، `packages/ui-native`) می‌مانند — هرگز داخل اپ‌ها.
4. هر اپ (web/crm/mobile/desktop) فقط یک **مصرف‌کنندهٔ قابل تعویض** از همان قراردادهاست.
5. تغییر UI نباید نیازمند تغییر بک‌اند، مدل داده، یا migration باشد — و بالعکس.

## پیامد

- بازبینی هر فاز شامل چک «آیا منطقی داخل کامپوننت قایم شده؟» می‌شود.
- اسکافولد CRM فاز ۲ (lib/api.ts، lib/auth، lib/i18n جدا از pages) الگوی مرجع است.
