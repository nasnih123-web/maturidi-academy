# Changelog — Maturidi Academy

All notable changes, newest first. Versions follow the GitHub releases;
the detailed prose notes live in `RELEASE_NOTES.md`.

## v1.1.0 — 2026-10-21

Post-release remediation release (Master Execution Prompt v2), developed
on `release/v1.1.0-remediation` from the v1.0.0 tree (`5bcdde87`).
Full evidence: `docs/audit-v2/` (audit report, final verification, done
criteria).

### Runtime & dependencies
- **Python 3.12 → 3.14.0** across the API stack, Dockerfile
  (`python:3.14-slim`) and CI. (The brief's "Python 3.15 stable" premise
  was checked against official sources on execution day: 3.15 is
  alpha-only; 3.14.0 is the baseline — `docs/RUNTIME_SUPPORT_MATRIX.md`.)
- **FastAPI 0.115.6 → 0.156.4** (starlette 1.9.0), pydantic 2.10.4 →
  2.14.1, SQLAlchemy 2.1.5, Alembic 1.20.0, pytest 9.1.1: all 8 deferred
  v1.0.0 advisories cleared; **pip-audit is clean and the CI
  `--ignore-vuln` flags are removed**.
- **Node 22.11.0 → 24 LTS** everywhere (`.nvmrc`, CI, web/CRM
  Dockerfiles — the Node 20 Dockerfile drift, audit F-11, is closed).
- Dependabot configured (`.github/dependabot.yml`): weekly grouped
  minor/patch proposals for pip, npm (web/crm/mobile) and
  github-actions.

### Security & MFA
- **MFA is now complete end-to-end** (closes Critical F-01 + High F-02):
  new `GET /auth/2fa/status`, authenticated `POST /auth/2fa/disable` and
  `POST /auth/2fa/recovery/regenerate` (both require password + second
  factor); CRM **Settings → Security & 2FA** page with QR enrollment,
  manual secret, one-time recovery codes (copy/download/confirm), status
  and re-auth modals; forced-enrollment routing for restricted sessions.
- **Scope-enforcement fix:** `2fa_setup`-scope tokens are now whitelisted
  in `get_current_user` — previously they could call every plain
  authenticated endpoint (profile, export, sessions, …). Plus a
  per-request DB re-check for privileged routes.
- TOTP steps are single-claim (replay-proof), recovery codes are hashed
  and single-use, regeneration replaces the set atomically, and all MFA
  actions are rate-limited and audit-logged.
- `UserOut` exposes real `roles`/`permissions`; the CRM permission gating
  no longer falls back to a permissive stub (F-07).

### Calculators (Phase 4, ADR-0022)
- Three source calculators (attributed to مهران ساعدی, dl.ghadimyol.ir;
  no license text — **rules re-implemented from scratch, no code/prose
  copied**): extended **zakat** (staircase nisab model, livestock
  tables, oshr, khoms), Hanafi **miras** (full Sirajiyyah pipeline,
  exact `Fraction` shares, honest stop states), and **mosaref** (Arabic
  verb conjugation — fully public).
- Golden batteries generated by running the original pages: zakat
  **131/131**, miras **53/53**, mosaref **41/41** (two documented source
  artifacts deliberately not reproduced).
- Source fiqh rules are seeded as v2 **DRAFT** configs; the public gate
  stays closed pending scholar review (`422 rules_not_approved`).

### Builds, mobile, desktop
- **CRM Builds is real machinery** (F-05): validated branding inputs,
  real GitHub `workflow_dispatch`, ARQ status sync
  (queued → running → completed/failed); unconfigured provider answers
  an honest `503 build_provider_not_configured`.
- **Mobile:** real icon/adaptive-icon/splash/notification assets
  generated from the school emblem (F-03); `eas.json` with
  development/preview/production-apk (+ AAB `production`) profiles
  (F-04); dynamic `app.config.js` — production profiles fail loudly
  without a real API URL, localhost is development-only (F-09).
  Real EAS builds remain **BLOCKED** on the owner's Expo account
  (MOBILE-EAS-01).
- **Desktop (ADR-0023):** local shell frontend replaces the impossible
  `../web/out` static export (F-06); production web URL is configured at
  packaging time; real Tauri icon set generated. Native builds run on
  CI runners — not tested in the dev sandbox.

### CI & quality gates
- **mypy 163 → 0 errors** and the CI Typecheck step is **blocking**
  (`continue-on-error` removed; the test that pinned the old arrangement
  now pins zero tolerance). mypy 2.4.0 pinned.
- **ruff baseline 160 → 133** (15 rules fully eliminated); the ratchet
  gate is unchanged and green.
- Test suite: **581 → 630 passed** (1 pre-existing skip), incl. 13 MFA
  tests, 12 calculator golden/exactness tests, and builds/desktop/deploy
  tests. Semgrep 0 findings; SBOM (CycloneDX 1.6) published in
  `docs/audit-v2/SBOM.cdx.json`.
- Migrations: up/down drill + backup/restore drill PASS (canonical

  model↔migration index/nullable drift — follow-up defined, not
  auto-fixed (`docs/SECURITY_REPORT.md` §5.1).

### Deployment

### Documentation

## v1.0.0 — 2026-10-20

First consolidated release on `main`: all 18 development phases (0–17)
plus three hardening/remediation passes and the production-readiness
mission, merged via PR #1 (merge commit `91125928`). Full notes:
`RELEASE_NOTES.md`.

- Full platform: FastAPI API, Next.js web, CRM, Expo mobile shell, Tauri
  desktop shell.
- Security remediation passes 1–3: server-side 2FA enforcement, atomic
  token rotation with reuse detection, one-time WebSocket tickets,
  S3/MinIO storage provider, fail-closed rate limiting, PDF validation,
  secret-hygiene sweep (gitleaks full history: 0 live credentials).
- CI hardening: ruff pinned (0.17.1) with a no-increase baseline gate
  (160 frozen findings), blocking semgrep + pip-audit + npm audit gates,
  Alembic migration check, Docker builds gated on all app jobs.
- Dependency security: Next.js 15.5.28, next-intl 4.9.2, Vite 6.4.4,
  react-router-dom 7.18.4.
- Tests at release: 581 passed + 1 skipped (clean env), 0 failed. Known
  debt at release: 159 mypy errors (non-blocking in CI), ruff baseline
  160, 8 pip-audit advisories deferred behind documented CI ignores —
  all three closed in v1.1.0.
