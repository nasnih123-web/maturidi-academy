# بسته‌های مشترک — آکادمی ماتریدی

قرارداد: توکن‌های طراحی و کتابخانه‌های کامپوننت در پکیج‌های جدا می‌مانند تا
لایهٔ نمایش بدون دست‌زدن به منطق کسب‌وکار قابل بازسازی باشد (ADR-001/0002).

## وضعیت بسته‌ها (بازبینی Track C — 2026-10-19)

| بسته | وضعیت | مصرف‌کنندهٔ واقعی |
|---|---|---|
| `design-tokens` | ✅ واقعی | `apps/web` (‏tokens.css، ‏geometry، ‏content-registry، ‏cartouche)؛ وابستگی `ui-native` |
| `ui-web` | ✅ واقعی | `apps/crm` (‏Button/Badge/Card…) |
| `ui-native` | ✅ واقعی | `apps/mobile` (‏RootNavigator، ‏HomeScreen، ‏AuthScreen) |
| `shared-types` | ❌ وجود ندارد | — |
| `icons` | ❌ وجود ندارد | آیکون‌ها داخل `design-tokens/motifs/` نگه‌داری می‌شوند |
| `config` | ❌ وجود ندارد | — |

**تصمیم:** بسته‌ای «فقط برای اسم» ساخته نمی‌شود. در بازبینی، تکرار مضری از
تایپ‌ها/آیکون‌ها/کانفیگ بین اپ‌ها دیده نشد که ساخت `shared-types`/`icons`/`config`
را توجیه کند (هر اپ کلاینت تایپ‌دار خودش را دارد؛ آیکون‌ها در design-tokens‌اند).
اگر روزی تکرار واقعی اثبات شد، بستهٔ جدید فقط با مصرف واقعی ساخته می‌شود —
نه اسکلت خالی.
